photo_backend 服务端部署简要说明（从 GitHub 克隆到上线）
更新时间：2026-04-20

0. 适用范围
- 本说明面向“拿到 GitHub 仓库地址后，如何把该 Go 后端部署到 Linux 服务器并跑起来”。
- 可选能力：
  - 构图分析（ONNX）：需要 Linux + cgo + onnxruntime 动态库。
  - VLM 多模态：Go 后端通过 HTTP 转发到独立的 Python 服务（可在 Windows GPU 机器上运行），也可通过 SSH 反向隧道让服务器访问。

1. 克隆源码
在服务器（或你的开发机）执行：

  git clone <你的GitHub仓库地址> photo_backend
  cd photo_backend

说明：把 <你的GitHub仓库地址> 替换为真实地址（HTTPS 或 SSH 均可）。

2. 服务器环境准备（Linux）
2.1 必备软件
- Git
- Go（以 go.mod 为准：go 1.25.0；建议安装与 go.mod 匹配或更高的小版本）
- MySQL（或可访问的 MySQL 实例）

2.2 若你要启用“构图分析(ONNX)”
需要编译工具链（cgo）：
- Ubuntu/Debian：sudo apt-get update && sudo apt-get install -y build-essential
- RHEL/CentOS：sudo yum -y install gcc gcc-c++ make

3. 数据库准备
3.1 创建数据库（示例）
在 MySQL 中创建：

  CREATE DATABASE photography_db DEFAULT CHARACTER SET utf8mb4;

3.2 配置连接 DSN
项目通过环境变量 PHOTO_DB_DSN 连接 MySQL。
示例（与项目默认一致）：

  root:123456@tcp(127.0.0.1:3306)/photography_db?charset=utf8mb4&parseTime=True&loc=Local

注意：首次启动会自动 AutoMigrate 创建/更新表结构。

4. 配置环境变量（推荐使用 /etc/photo_backend.env）
仓库已提供示例：deploy/systemd/photo-backend.env.example

4.1 拷贝并修改
（以 root 用户在服务器为例）

  sudo cp ./deploy/systemd/photo-backend.env.example /etc/photo_backend.env
  sudo vi /etc/photo_backend.env

关键项：
- PORT：Go 服务端口（默认 8080）
- PHOTO_DB_DSN：MySQL DSN（按你的账号密码/地址修改）
- GIN_MODE：建议 release

可选项（推理相关）：
- COMPOSITION_MODEL_PATH：构图模型 onnx 路径（默认 models/comp_model.onnx）
- ONNXRUNTIME_SHARED_LIBRARY_PATH：Linux onnxruntime 动态库路径（例如 /root/onnxruntime-.../lib/libonnxruntime.so）
- VLM_API_BASE_URL：VLM 服务基础地址（例如 http://127.0.0.1:18000）
- VLM_HTTP_TIMEOUT_SECONDS：Go 调 VLM 超时（默认 120，可按需调大）

提示：如果你从 Windows 拷贝 env 文件到 Linux，可能带 CRLF，必要时执行一次：

  sudo sed -i 's/\r$//' /etc/photo_backend.env

5. 编译 Go 服务（二进制）
建议在“目标服务器”上直接编译（尤其是 ONNX/cgo 场景）。

  cd /root/photo_backend
  CGO_ENABLED=1 go build -o photo_backend_server .

说明：
- 生成的二进制为 /root/photo_backend/photo_backend_server
- 如果不需要构图(ONNX)，也可以编译但不配置 ONNXRUNTIME_SHARED_LIBRARY_PATH；构图功能会降级不可用，服务仍可启动。

6. 运行与守护（systemd，推荐）
仓库已提供示例 service：deploy/systemd/photo-backend.service

6.1 安装 service 文件

  sudo cp ./deploy/systemd/photo-backend.service /etc/systemd/system/photo-backend.service

如你的部署目录不是 /root/photo_backend，请同时修改 service 中的：
- WorkingDirectory
- ExecStart

6.2 启动并设置开机自启

  sudo systemctl daemon-reload
  sudo systemctl enable --now photo-backend

6.3 查看状态与日志

  sudo systemctl status photo-backend --no-pager
  sudo journalctl -u photo-backend -n 200 --no-pager

7. 手动运行（不使用 systemd 的情况）
在仓库根目录（必须保证当前工作目录能正确找到 ./static）：

  cd /root/photo_backend
  set -a; source /etc/photo_backend.env; set +a
  ./photo_backend_server

8. 可选：VLM（Python 推理服务）部署/联调
如果你需要 /api/vlm/infer 能工作，需要部署 Python 推理服务（vlm_api）。

8.1 同机部署（Linux 上直接跑 Python 服务）
- 参考仓库 vlm_api/README.md
- 让 VLM 服务对 Go 可达（同机一般用 http://127.0.0.1:8000）
- 在 /etc/photo_backend.env 设置：VLM_API_BASE_URL=http://127.0.0.1:8000

8.2 推荐联调形态：Windows(GPU) 跑 VLM + SSH 反向隧道
- Windows 上启动 VLM（示例）：

  python -m uvicorn app:app --host 127.0.0.1 --port 8000

- Windows 上建立 SSH 反向隧道，把“Windows:8000”映射到“服务器:18000”（示例）：

  ssh -N -R 127.0.0.1:18000:127.0.0.1:8000 root@<server_ip> -p 22 -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3

- 服务器上配置 Go 指向隧道端口：

  VLM_API_BASE_URL=http://127.0.0.1:18000

更完整流程见：docx/启动说明.md

9. 验收方式（建议）
9.1 确认服务端口监听
- 默认：0.0.0.0:8080

9.2 测试一个无需登录的接口（示例：热门模板）
在服务器上执行：

  curl -sS http://127.0.0.1:8080/api/templates/hot

9.3 静态资源是否可访问
静态资源挂载在 /static，对应仓库 ./static 目录。
例如（路径按你的实际文件存在情况调整）：

  curl -I http://127.0.0.1:8080/static/avatars/

10. 常见坑
- WorkingDirectory 不对：static 目录通过相对路径 ./static 暴露；用 systemd 时务必保持 WorkingDirectory 指向仓库根目录。
- ONNX 不可用：优先检查 ONNXRUNTIME_SHARED_LIBRARY_PATH 与 COMPOSITION_MODEL_PATH 是否正确；缺失时构图功能会降级。
- VLM 超时：检查 VLM 服务是否在线、Go 服务器能否访问到 VLM（隧道是否断开、端口是否占用），必要时增大 VLM_HTTP_TIMEOUT_SECONDS。
